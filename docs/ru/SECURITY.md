# Политика безопасности

## Сообщения об уязвимостях

Если вы обнаружили потенциальную уязвимость в Worker SDK, пожалуйста, не открывайте публичное Issue. Вместо этого отправьте письмо на адрес [madgagarin@gmail.com].

## Модель безопасности

Worker SDK является ключевым компонентом экосистемы Avtomatika и спроектирован с приоритетом на безопасность:

1.  **Mutual TLS (mTLS)**: Поддержка клиентских сертификатов для защищенного и аутентифицированного взаимодействия с оркестратором.
2.  **Динамическая ротация токенов**: Автоматическое обновление STS-токенов доступа без необходимости перезапуска воркера.
3.  **Строгая изоляция**: Каждая задача выполняется в собственной временной директории (`TASK_FILES_DIR`). Данные одной задачи недоступны для другой.
4.  **Автоматическая очистка**: Временные данные задачи безвозвратно удаляются сразу после её завершения или сбоя, чтобы предотвратить накопление данных.
5.  **Защита конфиденциальных данных**: Ключи доступа S3 и токены оркестратора передаются только через переменные окружения или защищенные объекты конфигурации и никогда не попадают в логи.
6.  **Целостность сообщений (HMAC SHA256)**: Воркер автоматически подписывает все исходящие сообщения (хартбиты, результаты, события) своим токеном. Это предотвращает подмену данных в пути.
7.  **Защита от атак повтора (Replay Protection)**: Все подписанные сообщения содержат временную метку (`timestamp`). Оркестратор отклоняет любые устаревшие пакеты, что делает невозможным перехват и повторную отправку ваших данных злоумышленником.

Смотрите полную [Модель безопасности HLN](https://github.com/avtomatika-ai/avtomatika/blob/main/packages/hln/SECURITY.md) для получения подробной информации об экосистеме.
